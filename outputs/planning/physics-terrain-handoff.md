- `core/rock-surface.ts` exports `RockSurface`. Construct `const roverSurface = new RockSurface(height)` before returning your world; return it as `roverSurface` (the optional field already exists on `MarsEnvironment`).
- After your transformed rock instances are all placed and their matrices current, call `roverSurface.add(mesh, worldMatrix)` for a single mesh, or `roverSurface.bake(scene)` for recognized named rock meshes/instances. `bake` currently recognizes `hub-layered-bedrock-*`, `hub-outcrops-*`, `hub-instanced-scattered-bedrock`, `hub-scanned-outcrop-preview`; tell physics via this file if your batch name differs, or call add for each instance matrix explicitly. Rasterization is once at setup, a 4 cm top-contact grid; no per-frame render-mesh raycasts.
- Mark the old rock navigation obstacle objects `kind:'rock'` (optional literal). Spirit and camera retain their old solid proxies; the rover skips those keep-outs only when the baked surface has actual cells. Non-rock obstacles continue blocking normally. Surface/contact height, not the keep-out circle, stops the rover at oversized ledges or belly obstruction.
- `new Vehicle(rover.contactConfig, world.bounds, world.roverSurface)` is already wired in `opportunity-drive.ts`. Its `settle` and `update` use the surface's wheel-radius envelope while receiving bare terrain height as the existing fourth argument. Dust and camera use surface.height, too. No changes to terrain100 morphology/materials/placement are needed.
- Call `roverSurface.clear()` on disposal. Ensure ready resolves only after baking.
